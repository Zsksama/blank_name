### T-001 搭建 Godot 工程目录与版本库基线

- **目标**：换一台机器 `git clone` 下来，用 Godot 打开就能 F5 进到战斗场景；仓库里不混入引擎缓存，目录结构一眼能对上 `07` 的规范；另有《使用说明》说清怎么打开、怎么跑、按键是什么。
- **依据**：07 第四、五节（目录与登记规范）；01 第十一节第 1 条（启动后能立刻在画面里看到…）；README 第二节（平台与必交发行版：可正常运行、正常退出）。
- **范围**：
  - 做：在**现有** GitHub 仓库里建立结构化目录（按 07 第四节的命名与层级；本项目用不到的 3D 子目录可省，省了要在日志里写一句）；建可运行的 Godot 工程与战斗主场景（空场景即可）；`.gitignore` 排除引擎缓存与导入缓存；提交并推送；在**程序专用文件夹**里写《使用说明》（打开方式、运行方式、按键、Godot 版本），并在开发日志里记一条。
  - 不做：不新建仓库；不改仓库根 `README.md`（说明放程序侧）；不做 GitHub→AtomGit 迁移（提交前统一迁）；不建正式美术资源；不规定节点结构、输入映射等实现手段（程序定）。
- **验收**：
  1. 在一台干净机器上克隆后，用《使用说明》里写的 Godot 版本打开工程无报错，F5 进入**战斗场景**而不是空白工程。
  2. 关闭场景窗口后进程正常退出，无残留进程、无报错日志。
  3. `git ls-files` 里没有任何引擎缓存/导入缓存路径；克隆后工程仍能直接打开运行。
  4. 仓库根能看到 `Assets/`（含 `Art`、`Audio`）、`Scenes/`、`Scripts/`、`LICENSES/`、`LICENSES.md`；能与 07 第四节逐项对上，省略项已在《使用说明》或日志注明。
- **优先级**：P0（框架必需）
- **依赖**：无。Godot 版本由天羽确定并写进《使用说明》，本卡验收以它为准。
- **交付**：分支自定，完成后在本卡下回填分支名 + commit 号；文件：目录结构、`.gitignore`、战斗主场景、程序侧《使用说明》与开发日志；演示：克隆 → 打开 → F5 → 关窗。

### T-002 搭建战斗场景与水道骨架

- **目标**：启动后画面里一眼能看出：左侧一块留空区（未来碉堡的位置）、右侧海域被分成 N 条横向水道、每条水道边界看得见；改同一个参数就能把 N 变成别的数。
- **依据**：01 第二节（横版侧视、数条平行水道、左侧碉堡、右侧来敌；条数见 Q1）；01 第十一节第 1 条；09 H01。
- **范围**：
  - 做：战斗场景（不含敌人）；左侧留空区（可见标识 + 可调宽度）；N 条横向水道的可见占位带与道边界；N 与分辨率都做成可调参数（默认值由天羽试出，待群里定）；占位贴图程序自产纯色块，走普通贴图资源与普通节点（编辑器里看得见、能换图）。
  - 不做：不做敌人与刷怪；不做开火；不画碉堡本体（只留空 + 标识）；不做经营与结局；不做正式美术；不规定用什么节点搭水道（程序定）。
- **验收**：
  1. 启动即见完整画面：左侧留空区、N 条水道、每条水道边界都能用肉眼分辨；画面里没有任何由脚本绘制/代码生成的色块，外观全部来自工程内贴图资源。
  2. 只改一个参数就能把水道数从 N 改成 M（N≠M），场景结构不用重搭；改完不报错、布局完整、留空区不被水道侵占。
  3. 左侧留空区在不同 N 下都保有自己的位置与可见边界，宽度可通过参数调整。
  4. 交出同分辨率下 N 与 M 两组的启动截图（真改过参数，不是画上去的），作为群里定 Q1 的材料之一。
- **优先级**：P0（框架必需）
- **依赖**：T-001（工程能跑）。
- **交付**：分支自定，回填 commit；文件：战斗场景、占位贴图、参数入口；演示：启动截图 + 改参数前后两张 + N/M 两组对比。

### T-003 实现玩家船与 WASD 道内移动

- **目标**：屏幕里有一艘玩家船（占位贴图），WASD 能动：A/D 沿当前水道左右走，W/S 在**有阻尼的过渡**里换到上/下一条道（不瞬移）；船始终被限制在水道内、进不了左侧留空区；改船体贴图大小后，能拿出几组对照给群里定最终分道数。
- **依据**：01 第三节（单船、换道有延迟）、01 第二节（移动限制：只在道间跳转、不做 Y 轴连续移动）；09 12:45 Q2、Q3；09 H01。**注**：A/D 沿 X 轴自由移动是主策划 11-21 口头补充，`01` 尚未写入，已记回传清单 N09。
- **范围**：
  - 做：玩家船（普通场景节点 + 自产纯色块贴图）；WASD 四向；A/D 沿水道横向移动并受左右边界限制；W/S 换道为带阻尼的过渡，过渡时长与阻尼系数可调（数值留空，Q3 未定）；到最上/最下道后 W/S 不再换道（不循环跳）；不能进入左侧留空区；分道数参数与船体贴图尺寸联动，产出对照截图。
  - 不做：不做开火与弹药；不做敌人；不做部位损伤、受击、碰撞伤害；不做正式美术；不选输入、物理或动画的实现手段（程序定）。
- **验收**：
  1. 四向可控：A/D 让船沿当前水道左右移动；W/S 让船换到上/下一条道；换道全程位置连续变化、能看出首尾加减速，不是瞬移到另一条道（逐帧截图或录屏可判断）。
  2. 边界可判定：船无法越过水道上下边界、无法进入左侧留空区；到最上/最下道后按 W/S 位置不变且不报错。
  3. 外观来自工程内一张贴图资源：在编辑器里换掉这张图即可改变外观、不用改脚本；运行时没有任何由代码生成/绘制的色块。
  4. 交出 3 组「分辨率 × 条数 × 船体尺寸」对照截图（每组注明分辨率、N、单条高度、船体贴图尺寸），给出你建议的一组与理由；最终条数由群里拍板，拍到后只改参数。
- **优先级**：P0（框架必需）
- **依赖**：T-002（水道边界与留空区）；换道具体数值等 Q3，不阻塞。
- **交付**：分支自定，回填 commit；文件：玩家船场景与贴图、移动参数；演示：换道过渡 3 帧截图 + 上/下边界各 1 张 + 换贴图前后各 1 张 + 3 组对照图。
