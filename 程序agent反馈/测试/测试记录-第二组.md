## 3. 关键发现：弹药池其实由**经营库存**决定，不是战斗里的 30/20/10

`Scripts\battle_manager.gd:617-618`：

```gdscript
for index in range(AMMO_KEYS.size()):
	_weapon.ammo[index] = _battle_start.ammo[AMMO_KEYS[index]]
```

也就是说每一场战斗的弹药，都是经营场景传过来的库存快照。真正的上游是：

```gdscript
# Scripts\Management\management_rules.gd:101
const INITIAL_STOCK := {
	"materials": 4, "research": 1, "ammo": {"round": 8, "chain": 4, "grape": 2},
}
```

`player_weapon.gd` 里的 `ammo = [30, 20, 10]` 只在「直接从 `battle.tscn` 启动」时生效，正常经营→战斗循环里会被库存覆盖。

### 这意味着

- 一关要击沉 14—18 艘，按 43 定的「普通船 3 发」算需要 **42—54 发实心弹**；
- 而库存初始只有 **8 发**，铸造一次 4 材料换 8 发、订单日产 2 发 —— **一关根本凑不出 40 发**；
- 所以 v2「第 2 关弹药见底、最后一个靠接舷解决」不是玩家打得浪费，是**库存设计**决定的必然结果。

### 为什么我没改

任务卡（`待派-数值调参-天羽.md`）明确写着「不动 `management_rules.gd`」。弹药产出、初始库存、铸造配方全在这个文件里，属于禁改区。

### 7.4 三条结论

1. **第 4 关的断崖被修掉了。** 改动前两轮都在第 4 关破堡（3:07 / 2:19，堡 0）；改动后接舷流 1:49 拿下、碉堡还剩 42。砍掉「强制 2 艘重船」有效。
2. **接舷流现在能一口气通关**：五关全胜、平均 105 秒（落在 43 的 90—150 秒目标内）、碉堡最低 42。这是第一次出现完整通关样本。
3. **火力流仍不成立，且出现时间失控**：第 2、3 关 3:48 / 3:52，是 43 上限（150 s）的 1.5—1.6 倍。而这轮打法是「骗敌人开火 → 换道躲 → 让碉堡打」，本质仍靠碉堡输出，只是把玩家的角色从“撞”换成“引”。

### 7.5 新发现：换道躲炮弹可能是可复现的「免伤循环」

v3-B 第 2、3 关打死 17 / 21 艘而碉堡只掉 7 / 58 点，说明「引诱开火 → 立刻换道」能大量规避伤害。

- 若是设计意图（走位躲弹是核心操作）→ 43 需要补一条“预期躲避率”，否则火力流会长期靠拖时间赢。
- 若不是设计意图 → 需要给换道加代价（换道期间受伤加成、或换道后 0.5 s 不能转向），否则玩家能无限拖。
