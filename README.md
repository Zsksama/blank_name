## 五、策划文档的存放与发布

`.local策划文件夹/` 是**本机工作区**，不进仓库、不发布。它里面有两层：

```
.local策划文件夹/
├── 00-策划案.md … 30-敌人开发规格.md   ← 编号小记（根目录，30 份）
├── 程序任务派发/                       ← 任务卡与流程
├── 文化考据组/                         ← 考据产出
└── 数值设计组/                         ← 数值待办清单
```

### 发布方式（手动）

只把**根目录下的编号小记**复制到一个新文件夹（就是当前的 `策划细节/`），提交那个文件夹。
**子目录不复制**——工作过程、任务卡、考据素材不公开。

### 给程序的读法

1. **任务卡单独发**（`30-敌人开发规格.md` 或 `待派-主角船.md`），不进仓库
2. 拿到任务卡后，按卡里的"依据编号"去 `策划细节/` 目录核对对应小记
3. 每份小记第一节都是主策划原话，一字未改；拿不准以原话为准

### 不进仓库的东西

| 内容 | 原因 |
| --- | --- |
| `.local策划文件夹/` | 本机工作区，含过程记录与内部讨论 |
| `文化考据组/官方文化素材/` | 约 600 MB，官方资料，不公开转发 |
| `备份策划.bat` | 本机脚本，路径写死 |

### 仍然建议遵守

1. **不要点 GitHub Desktop 的 "Discard all changes"**——它会连未跟踪文件一起清掉（11.22 已因此丢过一次，靠 stash 找回）
2. **收工前双击 `备份策划.bat`**：文档打包到 `D:\2026策划备份\`（约 300 KB）
3. 全局忽略已配置，切分支不会误收录 `.local`

详细工作方式见 [.local策划文件夹/agent.md](.local策划文件夹/agent.md)。
