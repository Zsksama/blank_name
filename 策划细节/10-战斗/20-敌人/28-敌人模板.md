# 三、部位数据结构（按你的数组形式）

## 3.1 形状

```text
parts = [
  [ 部位ID, 当前血量, 血量上限, 受击倍率[实心,破帆,爆炸], 碰撞箱, 状态 ],
  ...
]
```

## 3.2 示例（E-01 倭船，占位值）

```text
parts = [
  [ "SAIL",   30, 30, [0.60, 1.80, 0.70], "软", "正常" ],   # 帆：破帆弹专克
  [ "HULL",   40, 40, [1.00, 0.25, 0.85], "硬", "正常" ],   # 舰体：实心弹最疼
  [ "CANNON", 20, 20, [0.85, 0.20, 0.95], "硬", "正常" ],   # 炮台：爆炸弹有效
]
```

## 3.3 每一列是什么

| 列 | 内容 | 说明 |
| --- | --- | --- |
| 1 | 部位 ID | `SAIL` / `HULL` / `CANNON`（舵与撞角没有碰撞箱，见下） |
| 2 | 当前血量 | 绝对值，不是百分比 |
| 3 | 血量上限 | 可升级（敌船是否升级待定） |
| 4 | 受击倍率 | **长度固定为 3**，对应实心 / 破帆 / 爆炸三种弹 |
| 5 | 碰撞箱 | "软"（穿透）/ "硬"（停弹）/ "无" |
| 6 | 状态 | 由 2/3 实时算出：正常 / 破损（≤0.75）/ 被破坏（≤0.1） |

**要增加的列**（我的建议，供你挑）：
- **传导权重**：该部位被命中时，向舵/撞角传导的强度（也可以单独放传导表，见第四节）
- **受损外观索引**：贴图状态编号，美术用
- **音效标签**：命中该部位播哪个音效

> 你说的"还有什么要增加的"，以上三列是我能想到的全部；不想加就保持六列。

## 3.4 舵与撞角

它们**不在 parts 里**（没有碰撞箱），但仍有血量与被破坏状态。

建议单独一个小数组：

```text
hidden_parts = [
  [ "RUDDER", hp, hp_max ],
  [ "RAM",    hp, hp_max ],
]
```

# 四、传导表（二维数组）

行 = 主命中部位，列 = 传导目标，值 = `[概率, 伤害比例]`：

```text
conduction = [
  #                舵              撞角
  [ [0.15, 0.30], [0.10, 0.30] ],   # 命中舰体
  [ [0.10, 0.30], [0.10, 0.30] ],   # 命中炮台
  [ [0.00, 0.00], [0.00, 0.00] ],   # 命中帆：不传导
]
```

- 行序与 `parts` 一致（帆/舰体/火器与弓手），列序为 舵/撞角
- 帆整行为 0，就是"打帆传不到舵"
- 数值全部可调，不写死在代码里

> 你说"如果有更高效的方法，让程序自己想"——数据结构由程序定，**我们只保证语义**：主命中部位 × 传导目标 × 概率 × 比例。

# 六、移出去的两块（后续单独讨论）

## 6.1 行为逻辑 → 已开 : `29-M13敌人行为逻辑.md`

模板里只保留这几个**供行为树读取的字段**：

| 字段 | 说明 |
| --- | --- |
| `speed` | 移动速度 px/s |
| `lane_index` | 出场航道 |
| `stop_distance` | 距堡多远停下输出（占位 320） |
| `min_gap` | 同航道最小间距（约 1.2 个船身） |
| `can_change_lane` | **默认 false**，首版不启用 |
| `lane_change_margin` | 换道时判"目标航道有人"的 x 阈值 |
| `lane_change_fail_reason` | 运行时记录，如 `"有人"`，调试用 |

> 行为树本身不写在模板里，模板只提供它要读的数。

## 6.2 出怪逻辑（你的第 5、6 点）

要在这块里谈：

- 波次怎么排（哪一波出什么、几条道）
- **士气放这里**：初始值、什么情况掉、掉到多少撤退
- **奖励放这里**：击沉给什么、撤退是否也给
- 难度如何影响出怪

> 也就是说：**模板只描述"这个敌人有什么"，不描述"它怎么行动、怎么出现"。**
