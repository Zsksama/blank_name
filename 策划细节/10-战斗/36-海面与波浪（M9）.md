# 一、目标

> **让海面"活"起来，但一点都不能影响战斗逻辑。**

三条硬要求：

1. 浪只在**视觉层**动：`lane_index`、命中判定、AI 全部不受影响
2. 每条道的浪**互不同步**，看上去是一片海，不是五条皮带
3. 美术到位后**只换贴图**，程序不用再改结构

---

# 二、四层结构

```
① 天空 / 海面底图      ← 等美术，整张，不变
② 每道一条「水线」      ← Line2D，程序生成，上下起伏
③ 浪边贴图              ← 沿水线平铺，先占位
④ 遮挡层                ← 水线以下，盖住船底
```

| 层 | 谁做 | 现在能不能做 |
| --- | --- | --- |
| ① 天空/底图 | 美术 | ❌ 等 |
| ② 水线 | 程序 | ✅ 现在就能做 |
| ③ 浪边 | **程序生成**（画一次、缓存） | ✅ 现在就能做 |
| ④ 遮挡 | 程序 | ✅ 现在就能做 |

# 三、水线（核心）

## 3.1 基本参数

| 项 | 值 |
| --- | --- |
| 每条道 | **一条 `Line2D`** |
| 水平范围 | X = 260 → 1280 |
| 采样间距 | 16—24 px（程序试） |
| 五道合计 | 约 260—390 个点/帧 |

## 3.2 波高（参考写法，浪形由程序定夺）

> 下面只是**参考思路**，实际怎么叠由程序决定；设计要求只有一条：**自然、不呆板**。

```
h(x, t) = A1·sin(k1·x + t·s1 + φi)
        + A2·sin(k2·x + t·s2 + φi·1.7)

y = 基准线 − h
```

| 参数 | 说明 |
| --- | --- |
| `A1` / `A2` | 主浪 / 细浪振幅 —— **程序自己调** |
| `k1` / `k2` | 空间频率 —— 程序自己调 |
| `s1` / `s2` | 时间速度 —— 程序自己调 |
| `φi` | **第 i 道的相位偏移 —— 程序自己调** |

> 只给一个要求：**五道必须肉眼看出不同步**。具体数值程序调出效果再回填。

## 3.3 起伏不能影响逻辑

- 幅度控制在"看得出但不是波浪滔天"
- **逻辑用的 y 一律不变**：`lane_index`、碰撞箱、命中判定都用基准线
- 起伏只写进 `wave_offset_y`（和 `lane_offset_y` 分开）

## 3.4 远近差异（重要的"深度感"）

五条道不是平铺的五条线，**越往上越远**。让它们看起来像一片海，靠三个递减：

| 项 | 远道（上） | 近道（下） |
| --- | --- | --- |
| 振幅 | 小 | 大 |
| 亮度 | 暗 | 亮 |
| 速度 | 慢 | 快 |

- 具体倍率程序调（例如最远道 ×0.6，最近道 ×1.2）
- **不加这个，五条道永远像五条平行的皮带**

## 3.5 最上面那条线（P0）特别处理

- P0 是**地平线**（远海边缘），不是航道水线
- 它**做轻微起伏**，但幅度远小于航道水线
- 颜色最淡，几乎融进背景

> 判据很简单：**把 P0 单独隐藏，画面应该几乎看不出变化**。

# 四、浪边：由程序生成（不依赖美术）

## 4.1 为什么让程序画

- 美术还没交付，但这一层**今天就得有**
- 浪边本身很简单：**一条亮线 + 稀疏泡沫**，程序画一次就够
- 以后美术给了更好的，**换文件即可**，结构一行不改

## 4.2 生成算法（启动时做一次，之后缓存）

```
W、H：尺寸程序试（例：512 × 40）
画布：全透明

① 主浪脊
   for x in 0 .. W-1:
       y = H*0.5 + A*sin(2π * n * x / W)
       # n 必须取整数 → 首尾必然相接，横向平铺无接缝
       在 (x, y) 画 1—2 px 宽的亮色
       颜色：顶部偏白，往下渐变成淡蓝

② 副浪脊（可选）
   振幅更小、颜色更淡、相位错开半个周期

③ 泡沫
   沿浪脊上下 2—4 px 随机撒白点，密度程序调
   x 落在边缘（< 8 或 > W-8）的点，**镜像复制到另一端**
   → 平铺时边缘处不会突然断掉

④ 导出 ImageTexture 并缓存，只生成一次
```

## 4.3 挂到水线上

| 项 | 做法 |
| --- | --- |
| `Line2D.texture` | 上面生成的图 |
| `texture_mode` | `TILE` |
| 每帧 | **只更新 points 的 y**，贴图自动沿曲线铺开 |

## 4.4 程序可调的参数

| 参数 | 说明 |
| --- | --- |
| W / H | 画布尺寸 |
| A | **图内**浪脊振幅（不是水线的振幅） |
| n | 一张图里有几个波峰 |
| 脊宽 / 颜色 | 亮线的粗细与色值 |
| 泡沫密度 | 白点数量 |

> 全部程序自己调，调出效果后把数值回填到本文件即可。

# 五、遮挡层

| 项 | 做法 |
| --- | --- |
| 目的 | 船底浸入水中的部分被"水"盖住 |
| 做法 | 水线以下填一块与水面同色的区域（`Polygon2D`，上边跟水线走） |
| 透明度 | 可调 `water_alpha` |
| 顺序 | 在"本道的船与炮弹"**之后**画 |

> 后坐力下沉、炮弹入水，都靠这层"被水吃掉"。

# 六、船随浪

```
读船头、船尾两点的浪高 h1、h2
  垂直偏移 = (h1 + h2) / 2
  倾斜角   = atan2(h2 − h1, 船长)
```

- 只动 sprite 与炮台，**碰撞箱、弹道起点、AI 都不动**
- **炮口暂时不跟浪走**（弹道起点保持逻辑位置），先看效果；如果视觉割裂再考虑，**性能优先级更高**
- 倾斜上限程序调（别让船看起来要翻）

---

# 七、局部扰动

| 事件 | 做法 |
| --- | --- |
| **船经过** | 船附近浪幅**平滑降低**（半径程序调） |
| **炮弹入水** | 落点两侧叠加**衰减波** + 小水花 |
| **巨浪**（后续） | 横扫数道的临时波形 |

三者都是"改某一段水线高度"，不改结构。

# 九、倒影（11-27 补，之前漏了）

| 对象 | 做法 |
| --- | --- |
| **所有船的倒影** | **玩家船 + 全部敌船**都要。把 sprite **垂直镜像**一份，压在水线以下，透明度低（0.25—0.35） |
| **炮弹倒影** | 所有炮弹都做；**箭矢除外**（太小看不出） |
| 跟随 | 倒影随船一起移动、一起倾斜，但**方向相反** |
| 裁剪 | 倒影不能超出本道水线以下的范围（被遮挡层裁掉） |
| 性能 | 每艘船多一个 sprite，数量不多可以接受；**同屏船多时要能一键关掉** |

> 倒影是"海的感觉"最便宜的一招——成本低、效果好。

# 十、碎片落水与小水花（11-27 补）

| 项 | 做法 |
| --- | --- |
| 来源 | 敌船被击中时掉落的**碎片/粒子**（木屑、帆布碎、铁屑） |
| 物理 | 碎片带一个抛物线落下（简单重力即可） |
| 落水 | 触到本道水线 → **生成小水花**（小、密集、快速消失） |
| 池化 | 粒子必须**对象池**，不能每帧 new |

> 这一条同时服务两个目的：**受击有反馈**，以及**水面被打扰**。

- [ ] 五条道的浪**肉眼不同步**

## 18.2 定案：不铺满，改成"沿水线撒点"（11-27 确认）

原因：

1. 水线的形状是**程序算出来的曲线**，而浪花是**固定形状**的图——连续平铺会和曲线打架，接缝处对不齐
2. 两张图反复平铺，**重复感会很明显**
3. 现在的两张图**未必做了无缝处理**（两端都是平的低浪，纹理不一定接得上）

**建议做法**：

- 水线本身仍由程序画（一条亮线）
- 浪花贴图作为**稀疏装饰**，沿水线随机摆放：
  - 间距随机（例如每 200—400 px 一个）
  - 随机选 1 / 2 两张之一
  - 随机**水平翻转**，减少重复感
  - 越远的道越小、越淡

> 这样**不要求无缝**，也不会与曲线冲突。
