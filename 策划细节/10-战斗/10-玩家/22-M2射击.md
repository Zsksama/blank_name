# 二、口径核对（冷却与后坐力）

## 2.1 冷却

### 你给的算例（原样记下）

- 三门炮，每门冷却 3 s；全好时总条 100%
- 开一发 → 66.6%
- 过 1 s → 77.7%（那门炮回了 1/3，折算 +11.1%）
- 三门全开 → 0%
- 过 1 s → 33.3%（三门各回 1/3，合计一门的分量）
- **但此时仍开不了炮**，因为没有一门真正冷却完成

### 由此暴露的问题

总百分比会骗人：33.3% 看着像"有一门好了"，实际一门都没好。你也说了后续可能要改成**三等分圆环，各段分别计时**。

### 显示方案（已定：三等分圆环）

- 圆环切成 N 段，**每段独立冷却**，各自填充
- **完全冷却后在圆环内部用数字显示可开炮数量**（如 2/3）
- 开火门槛：至少一段满

## 2.2 后坐力（18:51 / 19:0x 修订）

| 项 | 结论 |
| --- | --- |
| 动画来源 | **全部用代码实现**，不需要美术画后坐帧 |
| 水平 | 与炮口朝向相反的水平位移 |
| 竖直 | **下沉用真实 y，但绝不改变所在航道**：航道是逻辑上的，y 只是连续显示 |
| 影响 | 因为是真的 y，所以**会改变炮口起点**，进而影响下一发的弹道 |
| 注意 | 下沉算法单独调，别让它被判定成"换道"，也别卡进地面/水面 |

> **接口提醒（重要）**：下沉和 M9 未来的海面起伏，都只改"视觉/起点 y"，**不能改航道索引**。
> 建议程序拆成三个量：`lane_index`（逻辑，换道才变）、`offset_y`（后坐下沉）、`wave_offset`（未来的浪）。
> 否则两个系统各改一遍 y，会互相打架。

## 2.3 炮口旋转（已确认）

- 单门炮可在 **0—180°** 旋转，**不能向下**
- **0° = 正前，90° = 正上，180° = 正后**（已确认）
- 这意味着**允许朝后开火**，背后的敌人也在射程内
- 多门炮**统一旋转**（共用一个角度）
- 你已标注：**后续可能还要改，要重点考虑**

## 2.4 弹道：抛物线 vs 带阻力

你问得对——**有阻力时轨迹就不再是抛物线**。

| 模型 | 数学形态 | 预测线怎么画 | 成本 |
| --- | --- | --- | --- |
| 真空抛物线 | 有解析解，`射程 = v²·sin2θ / g` | 一次算完 | 最低 |
| 线性阻力 | 有解析解，带指数项 | 解析或步进 | 低 |
| **二次阻力** | 无解析解，必须数值积分 | 只能步进模拟 | 低 |

### 关于"竖直朝上是否受阻力影响更大"

**是**，三个原因叠加：

1. 阻力与速度平方成正比，速度越快掉得越狠，竖直发射全程速度都高
2. 竖直弹道滞空久，阻力作用时间长
3. 水平发射有"重力帮忙加速"的下落段，竖直发射没有

所以同样初速，竖直射高会明显低于无阻力公式——这正好做出"仰角太高反而打不远"的手感，是个可用的深度点。

### 实现建议：一套积分器，预览与实战共用

```
step(dt):  v += (-k·|v|·v + g) · dt
           p += v · dt
```

- 预览：每帧用固定 dt（如 1/60）跑 60—120 步，把点连成虚线
- 实战：子弹用同一个函数、同一个 dt 推进
- 好处：**预测线和真实弹道永远一致**（两者用不同算法是这类游戏最伤信任的 bug）
- `drag_k` 做成变量，设 0 即纯抛物线，方便对比手感
- 步进设上限（如 180 步），防止贴地飞行无限算
