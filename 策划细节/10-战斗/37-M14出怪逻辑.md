# 一、本轮已定（11-25）

| # | 规则 |
| --- | --- |
| 1 | **气焰总量 = 剩余敌船数 / 初始敌船数**（如 14/14），由此算百分比 |
| 2 | **气焰最低 1%**——因为撤退也计入被击败，数值可能被扣到 0 以下，所以设下限 |
| 3 | **穷寇**状态（气焰 < 0.10）的敌人会**向右撤退** |
| 4 | 撤退退到**画面外**时，视为**被击败** |
| 5 | **全部敌人被击败 = 本场胜利** |
| 6 | 特殊敌人：在场时**气焰始终不低于 0.15**（接口，后续设计） |

## 1.1 关键：胜利不是"气焰归零"判定的

```
击沉敌船 → 气焰下降
气焰跌破 0.10 → 敌人进入穷寇 → 向右撤退
退到画面外 → 判为被击败
全部被击败 → 本场胜利
```

> 所以以前说的"削减敌人士气到阈值就胜利"，**本质是这条链的结果**，不是一套独立的胜利判定。
> 出怪与胜负只用**一套**：全灭即胜。

## 1.2 推论

- 14 艘的场次，气焰 0.10 ≈ 剩 1.4 艘 → 剩 1 艘时全体撤，玩家会看到"最后那艘掉头跑了"
- 有特殊敌人在场时，气焰被锁在 0.15 以上 → **永远不会触发穷寇撤退**，必须打完

# 三、气焰的数值机制（11-25 补）

- **气焰是全场唯一的一个值**，所有敌人共享；没有个体气焰
- 本质值 = `当前敌人数 / 初始敌人数`
- 击沉一艘分两步扣：**立即扣 0.5 ± 0.1**，剩余在约 **2 s** 内缓缓补完
- 事件加减：最终在本质值上做加减，再夹到 **[0.01, 1.0]**
- **撤退判定用最终气焰**（含事件修正），所以「靠打士气把敌人打崩」是一条真实存在的胜利路径

# 四、风险提示

| 风险 | 说明 |
| --- | --- |
| **双重判定** | 不要把"气焰归零"和"全灭"写成两套胜负逻辑，只保留"全灭即胜" |
| **转身即判胜** | 撤退中的船要等**完全离开画面**才计为被击败，否则玩家会看到"刚掉头就赢了" |
| **气焰扣成负数** | 已设下限 1%，但结算时要夹一次，防止 UI 显示负值 |

# 五、撤退的表现与实现（11-25 补）

- **气焰是一个全局值**，但撤退**不是全局脚本让所有船一起掉头**
- 气焰跌破 0.10 后，**每艘敌船在自己的行为树里进入「撤退」状态**；视觉上聚合成"全体撤退"
- **撤退时敌船贴图要左右镜像**——否则看起来是倒车，很怪
- 撤退到**完全离开画面**才算被击败；离开前仍可被击沉
- `morale_bias` **每场战斗重置**，不跨场累计
- 气焰条**只显示百分比**，不显示数量比；数量比是别处的 UI

# 七、出怪：费用制（11-26 草稿）

## 7.1 一句话

> **每一关有一个敌人总只数和一笔费用；出怪就是拿这笔钱去"买"敌人，便宜的买得多、贵的买得少。**

## 7.2 核心循环

```
关卡开始
  ├─ enemy_total（本关敌人总只数，如 12）→ 同时是气焰的分母、HUD 的 0/12
  ├─ total_budget（本关费用池）
  └─ 每 spawn_interval（占位 6—10 s 随机）开一次批次：
       ① 随机决定这批想出的个数：1—5
       ② 从"本关允许的敌人池"里逐个抽
       ③ 每次抽取扣该敌人的费用；余额不够就停
       ④ 已出只数不能超过 enemy_total
       ⑤ 选道（由阵型决定）
总只数出完 或 费用花完 → 停止出怪
场上清空 → 全灭 → 本关胜利
```

## 7.3 参数（占位，交数值组）

| 项 | 占位 | 说明 |
| --- | --- | --- |
| `enemy_total` | 12 | 本关敌人总只数；气焰分母 |
| `total_budget` | 60 | 费用池 |
| 单批个数 | 1—5 随机 | 实际能出几个还受费用约束 |
| 出怪间隔 | 6—10 s 随机 | |
| 同屏上限 | 8 | 防止一屏堆太多（性能） |
| 敌人费用 | 轻 3 / 中 5 / 重 8 | 原型阶段三种 |

## 7.4 特殊规则（关卡配置）

每关可以带一组"限制"，用来控制节奏与教学：

| 规则 | 例子 |
| --- | --- |
| **白名单** | 第 1 关只允许出「轻船」 |
| **黑名单** | 前 3 关禁止「重船」 |
| **必出** | 第 4 关至少出 2 只「重船」 |
| **必出（配额）** | 第 6 关必须出满 3 只「撞角船」 |
| **阵型池** | 每关从 2—3 种阵型里随机选 |

> 白名单与黑名单二选一，不要同时写，避免冲突。

# 八、11-26 修订：先定敌人列表，再随机出（取代 7.2 的实时扣费）

## 8.1 为什么改

实时扣费用会让"每批出几个、出多贵"的随机性过大，**敌人强度不可控**。

## 8.2 修正：总数是"算出来"的（11-26 晚）

**关卡只给一笔钱，敌人是拿这笔钱"买"出来的；买完剩多少只，那一关就是多少只。**

```
关卡预算 level_budget（例：60）× 难度系数（1.0 / 1.5 / 2.0）
  money = 预算
  list = []
  ① 先放入「固定必出」项（例：至少 2 只重船）——**必出项不占预算，白送**
  ② 反复随机抽敌人：
       抽到的费用 ≤ money  →  放进 list，money 扣掉
       否则                 →  重抽 / 跳过
       直到 money < 最便宜敌人的费用
  → list 的只数 = enemy_total（气焰分母、HUD 的 0/N）
```

**算一遍**（预算 60，轻 3 / 中 5 / 重 8）：

| 步骤 | 结果 | 余额 |
| --- | --- | --- |
| 必出 2 只重船 | list = 2 重 | 44 |
| 随机抽到 中、中、轻、重 | +5 只 | 44−5−5−3−8 = 23 |
| 随机抽到 中、轻、轻、中 | +4 只 | 23−5−3−3−5 = 7 |
| 再抽到 中 | +1 只 | 2 |
| 余额 2 < 最便宜的 3 → 停 | **共 11 只** | 2（浪费） |

> 所以**不需要预先定"每关几只"**——只用定预算，只数会自己长出来。

## 8.3 难度

- 难度乘的是**预算**：× **1.0 / 1.5 / 2.0** → 钱多，只数自然变多，构成比例不变
- 不另外设"每关固定只数"

## 8.4 出怪顺序（11-26 晚）

- **开局的前 20%（按只数）优先出低费敌人**，让玩家先热身
- 之后的 80% 从列表里**随机抽**
- 阵型批次照旧按阵型走

## 8.4 阵型

| 批次类型 | 个数 | 选道 |
| --- | --- | --- |
| **阵型批次** | 按阵型（2—3 个） | **按阵型决定** |
| 普通批次 | 随机 1—5 个 | 随机 |

- 阵型需要史料依据（见考据提示词）
- 阵型批次的出现概率、哪几种阵型，后续定

## 8.5 参数（占位）

| 项 | 值 |
| --- | --- |
| 关卡预算 | 60（再 × 难度） |
| 同屏上限 | **15** |
| 批次间隔 | 6—10 s |
| 普通批次个数 | 1—5 |
| 阵型批次个数 | 2—3 |

# 十四、长蛇阵分歧（11-28 · **未定，待主策划拍板**）

## 14.1 分歧是什么

| 谁 | 说法 |
| --- | --- |

| **程序自己的常规限制** | 普通批次「**每道最多 2 艘**」——阵型批次显然绕过了这条 |

## 14.2 为什么程序会这么改

U-06 ⑥ 提的是"**实机看不出阵型**"。鱼贯入场 = 一艘接一艘，玩家看到的是"这道怪多"，**看不出"这是一支队"**；整批入场才叫"首尾相接的一列"，可读性直接解决。

而且长蛇的目的本来就是「**逼玩家去那条道**」（§六），5 艘比 3 艘更"逼"。

## 14.3 两个待定

| # | 问题 | 选项 |
| --- | --- | --- |
| 1 | 长蛇到底几只 | **A 保持 5 只**（可读性最好，压力最大）／ B 收到 **3—4 只**／ C 回原案 2—3 只鱼贯 |
| 2 | 「每道最多 2 艘」是否对**阵型批次**豁免 | **A 豁免**（写进规则，免得下次验收打架）／ B 不豁免（那就做不成 5 艘长蛇，等于选 14.3-1 的 C） |

## 14.4 我的建议

**选 A + A，但加两条约束**

1. **长蛇只在前 3 关出现**（第 4/5 关池子里重船多，5 艘同进一道会和重船叠成灾难）
2. **该道整批未走完前，同道的普通批次暂停**（程序已实现"整批等待"，确认这条也在）

理由：可读性优先，但把"最密的那一下"限制在敌人构成还比较轻的前半段。

> **未定期间**：程序按现状（5 只、豁免）继续跑，不影响开发；等主策划拍板后改这条和 §六。
