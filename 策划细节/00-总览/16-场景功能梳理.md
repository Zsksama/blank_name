# 一、战斗场景

## 1.1 位置概况

- **2D 横版分道塔防**
- 最左侧：**碉堡**
- 碉堡右侧：**海洋**，被分成多条**航道**
- 玩家与敌人的船只在航道内移动、战斗
- **Y 轴不连续（分道），X 轴连续**

> **2026-11-23 重构图定案**（草图：`30-美术与设定/草图/20261123-战斗场景重构.jpg`，编号 H08；玩法细节见 `10-战斗/40-堡/33-M15碉堡模板.md`）
>
> | 项 | 定案 |
> | --- | --- |
> | 航道数 | **5 条** |
> | 堡的位置 | 画面最左，**纵向贯穿全部航道** |
> | 水门 | 位于**第 3 条航道（正中）**；玩家船的出生、回港、复活都走这里 |
> | 堡的火力 | **按道分配**，开局 4 门（道 1/2/4/5），水门道是**盲道** |
> | 敌人破堡 | 敌人从水门灌入 → 本场失败（PvZ 式） |
> | 画面顶部 | 状态栏：部件状态 + 换弹冷却环 ← **样式待定** |

## 1.2 碉堡

| 项 | 内容 |
| --- | --- |
| 攻击 | 敌人进入攻击范围后自动开火 |
| 受击 | 敌人会攻击碉堡 |
| 掉灯火 | 碉堡血量低于阈值后，再受击 → **灯火值降低** |
| 归零 | 碉堡血量清零 = **本次战斗失败**，并**大幅降低灯火** |
| 失败次数 | 不同难度有不同"可承担失败次数"**【待定】**；次数归零后再失败 = **本局失败** |
| 结局分支 | 本局失败时若不选择回档 → **直接进入结局** |
| 升级 | 可升级 |
| 自动修复 | **每次经营阶段结束后，自动修复一定血量** |

> **2026-11-23 细化（以 `33-M15碉堡模板.md` 为准）**：
> - 掉灯火：改为**按档**——跌破 60% / 25% / 归零各触发一次，不再按"每次受击"算
> - 归零：不是单纯判负，而是**敌人从水门灌入**（PvZ 式演出）→ 本场失败 → 扣兜底 → 归零进结局
> - 自动开火：**按道**，没炮的航道堡没有输出（盲道）
> - 战斗中**不自动修复**；经营后修到 70%（占位）

## 1.3 海洋 / 航道

- 战斗主场地，多条平行航道
- 船只只能在航道内移动（Y 轴不连续）

> **2026-11-23 验收细化：画面分层与海平面（重要，以本条为准）**
>
> 画面从上到下只有两层：**顶部：天空 + UI** ／ **下方：海道区**。海道区放 **5 条道**。
> （此前的错法是：把最上面那条"天空+UI"的带子也当成了一条海道。）
>
> | 规则 | 内容 |
> | --- | --- |
> | 海平面 | 每条道是一条**直线**（＝该道的海平面），后续美术替换成波浪线 |
> | 海面上方 | 是**海洋背景**，图层按"从上到下 ＝ 由远到近"排 |
> | 船的纵向位置 | 船底**贴着或略低于**本道海平面；**只有后坐力动画**才允许船体部分沉入本道海平面以下 |
> | 不压道 | 船底不能压进下一条道 |
> | 炮弹 | 可掉到**本道**海平面以下；**视觉上可以越过上方道**；**绝不能出现在下方道** |
> | 遮挡 | **下方道的海平面不能遮住上方道海面以下的背景**——海背景必须连续 |
>
> 当前实现与这条的差异，见 `10-战斗/10-玩家/验收-主角船-v1.md` P-01—P-05。

## 1.4 玩家船

### 移动与攻击
- 只能在航道内移动
- **鼠标瞄准**发射炮弹（首次明确：不是自动索敌）
- 可选择**多种炮弹**与**多种发射方式**

> **2026-11-23 验收补充**：
> - **船速**：改为当前实现的 **1/10 再略低**（具体 px/s 待实测填数）
> - **换道限制**：换道过程中**不能左右移动，也不能开炮**
> - 埋点：主策划标注"不能左右移动，手感可能不会特别好"，先做出来实测再定
> - 详见 `10-战斗/10-玩家/验收-主角船-v1.md` P-07 / P-12

### 部位血量
- 船体**各部位有独立血量**
- 敌人命中某部位时，会在**该部位及附近部位**造成伤害
- 部位血量分三档：**正常 / 破损 / 被破坏**
- 非正常状态产生对应 **debuff**

### 击沉
- **舰体部位**血量归零 → 被击沉
- 被击沉时**考虑显示船长的名字**（尝试取自真实史料）**【待定：取自哪份史料】**
- 需要**时间复活**
- 击沉会**降低灯火**

### 修理与升级
- 玩家船可升级
- 当各部位**非满血**时，会**随船只等级与升级内容不断自动修理回血**

## 1.5 接舷战（两船靠近时触发）

```
接舷判定
 ① 撞击：比对双方相对速度 → 按速度造成伤害（可能还要考虑防御力【待定】）
    画面上出现较大的"撞击！"文字
 ② 接舷：镜头拉近（可能需要暂停其他船只）
    按己方战斗力 vs 敌方战斗力交手，双方各部位持续掉血
    舰体先归零的一方沉没，同时大幅增加/减少对方士气
 ③ 退出：按某个键可强行退出接舷
    己方船只向左撤退较远距离，己方各部位大量掉血，敌方士气上升
```

> 设计意图（你的原话）：**所以正常情况下，没有十足的把握，要和敌方船只保持一定距离。**

## 1.6 敌方

- **多艘战船同时行动**，不同种类有不同战斗风格，各自选择进攻策略
- 敌方士气**初始 100**
- 敌船也有部位损伤机制：**被损伤时降低士气**
- 敌船被击沉 → **大幅降低士气**
- 士气降到阈值 → **撤退**，判定**本次战斗胜利**
- 具体机制 **【待定，后续讨论】**

## 1.7 胜负

| 结果 | 触发 |
| --- | --- |
| 胜 | 敌方士气跌破阈值撤退 |
| 负（本次战斗） | 碉堡血量归零 / 玩家船被击沉（沉船不等于战斗失败，见 1.4） |
| 负（本局） | 可承担失败次数归零后再失败 → 回档或进结局 |

# 二、经营场景

## 2.1 布局

| 区域 | 内容 |
| --- | --- |
| **上方** | 状态与资源栏：材料、各类弹药数量、研究点、灯火状态、日历、战船与碉堡的等级和破损度 |
| **左侧** | 罗盘选择器 + 物资变化预测 UI |
| **中央** | 剧情文本栏 + 事件统计栏 + 事件选择栏 + 选项选择栏 |
| **右侧** | 记账本 |
| **右下** | 鸣金 |

## 2.2 资源

| 资源 | 产出 | 用途 |
| --- | --- | --- |
| **材料** | 每回合自动产出，受**灯火状态修正**；也可由上回合事件获取 | 升级 / 维修战船与碉堡 / 制造弹药（**升级也许只需研究点【待定】**） |
| **弹药** | 每回合自动产出；可由事件获取；可用材料制造 | 战斗消耗。**暂定三种**，**暂定两种发射方式**；不同发射方式消耗量不同 |
| **研究点**（暂名） | 每回合自动产出，受灯火修正 | **用于升级** |
| **灯火状态** | 0—100，初始值按难度定；分三档：**渺茫 / 温和 / 明亮** | 影响各类事件与每回合资源产出；因战斗与经营而涨落 |
| **日历** | — | 增加沉浸感，兼作关卡显示 |

## 2.3 罗盘选择器与物资预测 UI

- 是**选项选择器之一**，与点击选项栏**等价**
- **常规经营事件**中，罗盘上方的事件会**闪光**——这就是**民众所呼的事件**，由灯火状态决定
- 选择闪光项 → **额外收益 + 灯火收益**
- 罗盘**始终指向当前选中项**，与选项栏不冲突
- 表现：可代码实现旋转动画，带**惯性与阻尼感**
- 罗盘下方：**物资变化预测**，如 `灯火+`、`材料-`、`弹药+++`

## 2.4 中央区

| 栏位 | 作用 |
| --- | --- |
| 剧情文本栏 | 显示当前事件文本，**可考虑配图** |
| 事件统计栏 | 本轮共有几个事件、当前第几个 |
| 事件选择栏 | 前后切换当前处理的事件 |
| 选项选择栏 | 显示事件选项 + **具体做法**（增加文化契合与沉浸感） |

## 2.5 记账本

记录**上回合及历史回合**的事件、所选项、具体物资变化。

## 2.6 事件类型

| 事件 | 内容 | 状态 |
| --- | --- | --- |
| **常规经营** | 积极备战 / 大力经营 / 平安度日（名字可优化） | 已有，细节待议 |
| **升级** | 船只、城镇等，类似技能树 | 已有 |
| **修理** | 修船只与碉堡。战斗中有自动修理，但大部分修理要在这里完成 → **需调低战斗中的修理速度** | 已有，数值待定 |
| **铸造弹药** | 是否要单独做成一个事件 | **待考虑** |
| **随机事件 1 个** | — | **不建议**：会导致数值不好处理 |
| **固定事件** | 结合文化背景的传统节日活动等 | 可能 |

## 2.7 鸣金

结束本次经营、开始下一场战斗。本轮经营的收益与战斗结果会在**战斗结束后**显现，并记入**下回合的记账本**。

## 2.8 核心循环

```
完成战斗 → 平稳的经营阶段 → 常规经营 → 升级 → 修理 →（铸造弹药？）→ 可能的事件 → 新的战斗
```

## 2.9 经营场景待定

- [ ] 升级是否要花材料（还是只花研究点）
- [ ] 是否保留"铸造弹药"事件
- [ ] 随机事件是否做
- [ ] 固定事件（节日）做不做
- [ ] **选了之后能不能改**：不能改便于程序、少 bug，但手感可能差；你的倾向是"选了就结算上一个事件"
- [ ] 事件数量与排列规则

# 三、两个场景之间的数据流

| 数据 | 战斗 → 经营 | 经营 → 战斗 |
| --- | --- | --- |
| 灯火 | 碉堡受击、击沉、失败 → 掉灯火 | 事件选项可涨灯火 |
| 材料 | 战斗不产出（待定） | 产出与消耗 |
| 弹药 | 战斗消耗 | 补充 / 制造 |
| 研究点 | — | 产出、用于升级 |
| 战船部位 | 战斗后受伤，经营里修 | 升级后回血更快 |
| 碉堡 | 战斗受损，经营后自动修复一段 | 修理、升级 |
| 敌方士气 | 战斗内使用 | 不跨场 |
