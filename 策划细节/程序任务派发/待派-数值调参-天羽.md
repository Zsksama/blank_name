## 目标

把战斗数值从"现在能跑通"调到"**有压力但不憋屈**"：玩家会掉血、堡会告急、一局 3—5 分钟能分出胜负。

**判定标准（主策划 11-28）**：当前**过于简单**——敌人打不动你，你一炮秒一片。

---

## 规则

### 1. 先拿版本

1. `git pull` 田的最新版本（**以田的版本为准**，别自己另开分支改战斗）
2. 先跑一遍现有测试，确认基线是绿的：
   ```
   godot --headless --path . --script res://Tests/Combat/test_enemy_ship.gd
   godot --headless --path . --script res://Tests/Combat/test_boarding.gd
   godot --headless --path . --script res://Tests/Combat/test_enemy_spawning.gd
   ```
3. 跑一遍**基线**：五关各打一局，记下"实际用时、掉多少血、堡剩多少"，这是对照底

### 2. 只改数值，不改结构

- 允许改：`@export` 数值、`.tres` 里的数值、常量
- 不许改：公式结构、行为分支、阈值语义（`0.75 / 0.10` 别动）
- **经营侧 `management_rules.gd` 不动**

### 2.5 四件必须守住的（详见 `43`）

1. **射程只改敌人**：玩家不动；普通敌箭 → 400—430，重船火铳 → 450—470
2. **停位 = 射程 × 0.95**；但**快船不停位**，行为树不许被停位卡死
3. **望楼锁定 + 实心弹 = 快船一发沉**（改耐久时必须保住）
4. **敌人必须比玩家慢**

### 3. 按这个顺序调（不要一次全动）

| 顺序 | 调什么 | 目标手感 |
| --- | --- | --- |
| **1** | **敌人射程**（只改敌人） | 玩家站最远处，普通敌人差一点点就能还手；重船和玩家差不多 |
| **2** | 玩家火力 ↔ 敌人耐久 | 一发要"值钱"：快船 2 发、普通 3 发、重船 6 发（锁定时快船 1 发） |
| **3** | 敌人火力 ↔ 玩家耐久 | 会玩能无伤；站桩会掉血 |
| **4** | 接舷伤害（下调） | **方向是更久**（现在约 7 秒），具体时长你设计，报实测值 |
| **5** | 帆损与撤退 | 配合 N-41：打残的船该跑不掉 |
| **6** | 关卡预算 / 难度方案 | 最后调，试 `43` 的 A/B/C 三方案 |

### 4. 每组改完必须实测

- 一组参数改完 → 立刻进游戏打 1—2 局
- **记一行**：参数名 / 原值 → 新值 / 为什么 / 实测结果
- 别"改十个再试"，那等于没改

### 4.5 必做的两个实验

| 实验 | 怎么打 | 目标 |
| --- | --- | --- |
| **高效** | 用对弹种、打对部位、跟望楼 | 一局打完**有盈余** |
| **低效** | 只用实心弹、打帆、不跟望楼 | 一局**肯定不够** |

两组发数差建议 ≥30%。这是判断"弹药够不够"的唯一依据，**不要凭感觉**。

### 5. 交付

一份 `数值调整报告.md`：

| 段 | 内容 |
| --- | --- |
| 基线 | 五关各一局的用时、掉血、堡剩余 |
| 改动表 | 一行一组，原值 → 新值 + 理由 + 实测 |
| 五关新基线 | 改完后各一局的同样三项 |
| 悬而未决 | 哪些调不下去、卡在哪、需要策划定什么 |

## 边界

- **不新增功能**，不重画贴图，不动 W-07 待发内容
- 不改接舷的**公式**（系数可以调）
- 不改出怪**规则**（间隔/上限/阵型逻辑），只调预算与费用
- 遇到"改数值改不动"的问题（比如某处硬编码），**记下来报**，别自己重构
- 射程调整本轮**先给结论**，不急着改
