## 三、T-101 炮台系统

**目标**：两门炮、统一旋转、以等级速度追随鼠标、角度限制在 0—180° 且不能向下。

**规则**

1. 炮台用**列表**实现，`turret_count = 2`，以后加炮只加元素
2. 所有炮**共用一个角度变量**（统一旋转）
3. 角度范围 `[0°, 180°]`：0° = 正前，90° = 正上，180° = 正后；**不允许负角度**（不能向下）
4. 瞄准算法：
   ```
   目标角 = atan2(鼠标 - 炮口原点)（限制到 [0,180]）
   当前角 += clamp(目标角 - 当前角, -角速度*dt, +角速度*dt)
   ```
5. `turret_angle_speed` 随等级提升（数值组给），默认值先给 120 °/s 占位
6. 炮口原点随船身与后坐力变化（见 T-109）

**边界**

- 鼠标在船身左侧时，角度会被夹到 180°，炮口停在正后，不会倒转
- 换道过程中**炮口仍可转**，只是不能开火

**验收**

- [ ] 鼠标绕船转一圈，炮口平滑跟随且始终在 0—180°内
- [ ] 鼠标在正下方时，炮口保持在 180° 或 0°（不穿模到船底）
- [ ] 改 `turret_count` 为 3，不需要改代码即可显示三门

## 四、T-102 冷却与圆环

**目标**：每门炮独立冷却，UI 是一圈分段圆环，中心显示可开炮数。

**规则**

1. 每门炮有 `reload_left`，开火时置为 `reload_time`（占位 5 s），随后线性递减
2. 圆环分为 `turret_count` 段，每段填充比例 = `1 - reload_left / reload_time`
3. 圆环中心数字 = 就绪炮数（`reload_left <= 0` 的炮的数量）
4. **开火门槛**：至少一段满（即可开炮数 ≥ 1）
5. 鼠标悬停圆环 → 显示每门炮的剩余秒数（只读）

**边界**

- 不要用"总百分比"作为唯一显示：三门全空时回 33% 仍不能开火，会被误读（这是主策划发现的问题）
- 冷却进度不存档

**验收**

- [ ] 两门炮：开一门 → 圆环 1/2、中心显示 1；全开 → 0/2
- [ ] 5 秒后两段依次填满，中心显示 2
- [ ] 中心数字与实际可开火数任何时刻一致

## 五、T-103 开火与弹道

**目标**：点击开火，实时抛物线，预览线与实战完全一致。

**规则**

1. 点击一次 = 发射一次（**不支持按住连发**）
2. 开火瞬间扣 1 发当前弹种；弹药为 0 时**无弹道、无音效、不进入冷却**
3. 弹道积分（固定 dt）：
   ```
   a = -drag_k * |v| * v + (0, gravity)
   v += a * dt
   p += v * dt
   ```
4. **预览线与实战共用同一个积分函数、同一个 dt**，步数上限 180
5. 射程由初速自然决定，不设"最大射程"参数
6. 换道期间禁止开火（`is_switching == true` 时忽略点击）

**边界**

- 低角度贴地飞行时，子弹在射程外或碰撞后退场，不能无限积分
- 子弹数上限建议 40，超出回收最早的

**验收**

- [ ] 预览线终点与实际落点误差 < 2 px
- [ ] 修改 `drag_k`，预览线同步变化
- [ ] 弹药 0 时点击无任何反应
- [ ] 换道中点击无效

## 六、T-104 齐射

**目标**：所有就绪炮同时开火，打几发扣几发。

**规则**

1. 齐射模式：遍历就绪炮，每门各发 1 发
2. 每门弹药各扣 1（就绪 2 门 = 扣 2 发）
3. 每门炮的发射角在基准角上随机 ±`spread_deg`（占位 5°）
4. 就绪 1 门时，齐射等同于单发（仍扣 1 发）
5. 就绪 0 门时不可开火

**验收**

- [ ] 2 门就绪时齐射，画面出现 2 发、弹药 -2
- [ ] 1 门就绪时齐射，只出 1 发
- [ ] 散布角可调，改为 0 时两发重合

## 七、T-105 弹药与切换

**目标**：三种弹药独立计数、无上限、切换有惩罚。

**规则**

1. `ammo[3]` 分别为实心弹、破帆弹、爆炸弹，**独立计数，无上限**
2. 切换弹种：`switch_ammo_delay`（占位 1.5 s）内不能开火，切换本身不消耗弹药
3. 当前弹种为 0 的不能发射（点击无效）
4. UI 三个弹药位显示各自数量

**验收**

- [ ] 三种弹药互不影响
- [ ] 切弹后 1.5 s 内点击无效，之后可正常开火
- [ ] 某弹种为 0 时该位置灰、点击不开火

## 八、T-106 命中与碰撞箱

**目标**：每船 3 个碰撞箱，帆穿透、舰体与炮台阻挡，跨道不判定。

**规则**

1. 每艘船挂 3 个 `Area2D`：`hit_sail`（软）、`hit_hull`（硬）、`hit_cannon`（硬）
2. 子弹命中时**先比 `lane_index`**：不同道 → 直接忽略（穿过去）
3. **帆（软）**：结算伤害后子弹**不销毁**，继续飞；记录已命中部位，防重复
4. **舰体（硬）**：结算伤害，子弹销毁
5. **火器与弓手（硬）**：结算伤害，子弹销毁；**同时对舰体结算一次伴随伤害**（系数由数值组给，占位 0.5）
6. 舵与撞角**没有碰撞箱**，只通过 T-108 传导受伤

**边界**

- 同一发子弹对同一部位只结算一次（用 `hit_parts` 集合）
- 子弹速度再快也不能在同一帧穿过两个部位重复结算

**验收**

- [ ] 打帆后子弹继续飞，能再命中后面的舰体
- [ ] 打舰体/火器与弓手子弹消失
- [ ] 炮弹飞过相邻航道敌船时**不触发任何结算**
- [ ] 同一部位不会被同一发子弹扣两次血

## 九、T-107 部位血量与三档

**目标**：5 个部位、血量绝对值、三档状态由比例实时算出。

**规则**

1. 部位：`HULL` 舰体 / `SAIL` 帆 / `CANNON` 炮台 / `RUDDER` 舵 / `RAM` 撞角
2. `part_hp` 与 `part_hp_max` 都是绝对值，`max` 可升级
3. 状态实时计算，**不单独存**：
   ```
   ratio = hp / max
   ratio <= 0.10 → 被破坏
   ratio <= 0.75 → 破损
   否则           → 正常
   ```
4. debuff 生效表（数值为占位，最终由数值组定）：

| 部位 | 破损 | 被破坏 |
| --- | --- | --- |
| 帆 | 移速 −30%、换道延迟 +20% | 移速 −60%、换道延迟 +50% |
| 炮台 | 该炮装填 ×1.3、伤害 −15% | 该炮无法开火 |
| 舰体 | 无额外 debuff | 沉没 |
| 舵 | 换道延迟 +40% | 无法换道 |
| 撞角 | 撞击伤害 −50% | 无法撞击 |

5. 部位环：UI 层，**不挂在船身上**，位置由主策划给（先用临时位置）

**验收**

- [ ] 血量跨过 75% / 10% 的瞬间，状态与 debuff 同时切换
- [ ] 只有 HULL 归零才沉没，其它部位被破坏只降效率
- [ ] 状态不写入存档（读档后由 hp 重算）

## 十一、T-109 后坐力

**目标**：开火有可见的位移与下沉，但**绝不改变航道**。

**规则**

1. 开火瞬间：
   - 水平：沿炮口反方向位移 `recoil_impulse`
   - 竖直：下沉 `recoil_sink`（**写入 `lane_offset_y`，不动 `lane_index`**）
   - 姿态：船头翘起 `recoil_pitch`
2. `recoil_recover_time`（占位 0.15 s）内回弹
3. 因为下沉改变炮口原点，**会影响下一发的发射位置与角度**
4. 三个参数默认 0（只保留接口），测手感时再调

**边界**

- 下沉不能把船推出可玩区域，不能触发换道判定
- 同时连续开火时位移叠加要有上限（避免把船推飞）

**验收**

- [ ] 参数调大后，开火可见船身后退与下沉
- [ ] `lane_index` 全程不变
- [ ] 下沉时下一发炮弹起点随之下移

## 十二、T-110 自动维修

**目标**：战斗中缓慢止血，但修不回"正常"档，必须回港大修。

**规则**

1. 每个部位独立自修，速率 = `repair_base_rate`（占位 0.5%/s）
2. 状态折扣：正常不回、破损 ×1、被破坏 ×0.2
3. **上限 = `max_repair_ratio`（占位 0.6）**：血量涨到 `max * 0.6` 就停
4. 因为 0.6 < 0.75，**战斗中永远修不回"正常"档**
5. 不消耗材料、不消耗弹药
6. 不做受击中断：挨打时也照常修
7. 船被击沉时不自修，走复活

**验收**

- [ ] 破帆能修到 60% 就停住，debuff 仍是"破损"级
- [ ] 把 `max_repair_ratio` 调到 0.8，可以修回正常档（验证上限是唯一开关）
- [ ] 自修不消耗任何资源
